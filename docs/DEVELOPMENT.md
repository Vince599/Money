## 本批已写入代码

| 范围 | 当前行为 |
|---|---|
| 金额 | 现金以 Int64 最小单位保存，解析与运算不用 Double；检查精度、币种和溢出 |
| 基础账本 | 支出、收入、同币种转账；资产与负债方向区分；内部生成平衡分录计算余额 |
| 历史实账 | 期初之前的支出也正常扣当前余额；余额更正独立记录差额，不计消费或收入 |
| 账户 | 创建钱包、银行卡、现金、储值、信用卡，设置期初与汇总范围；储值默认不纳入；默认记账账户可选 |
| 国内账户模板素材 | 31 个机构标志、8 个通用回退、54 个模板；JSON 清单生成 Swift 目录、Xcode imageset 和离线预览。仅素材与调用接口就绪，新增／编辑页面及呈现字段持久化尚未接入，详见[开发参考](ACCOUNT_TEMPLATES.md) |
| 资料维护 | 账户改名、停用及汇总开关；分类／主体新增、改名、启停，分类图标可选；默认主体可设；历史记录保留 |
| 分类目录 | 新账本普通中文种子共 100 项（20 个一级、80 个二级），保留已有 ID；已有账本的用户目录不被覆盖 |
| 流水修改 | 编辑保留事件身份和创建时间、检查版本；删除撤销影响；旧操作 ID 保留防重标记 |
| 记账输入 | 收支与转账切换保留公共字段，各自分类保留；一份自动草稿；保存及保存并继续 |
| 金额计算器 | 四则运算、括号、标准优先级、清除退格；精确有理数中间运算，仅最终按分四舍五入并提示；表达式随普通草稿保存，正式流水只存计算结果 |
| 流水查找 | 标题／备注字面搜索；方向、转账双端账户、一级／二级分类、主体、币种、金额上下限和发生日期组合筛选；停用资料仍可查询历史，无结果与空账本分开显示 |
| 复制流水 | 新身份、新操作 ID、默认当前日期；先建立草稿，覆盖旧草稿须确认；停用账户与分类待重选，有效主体回退；原记录不变 |
| 保存一致性 | 正式入账、草稿更新同事务；序号保护延迟请求；失败保留旧数据库状态和输入 |
| SQLite | 规范化核心列、精确整数金额、外键、操作唯一约束；普通新建／编辑只写目标行并同事务处理草稿；完整模型载荷与关键列互相核验；拒绝未知版本和坏库 |
| CSV ZIP | `ledger-core-v1` 固定 12 份 CSV，包含本版全部核心字段、设置、草稿和退役操作 ID；字段字典、计数与原始字节 SHA-256 随包保存 |
| 恢复 | 系统文件选择 → 校验与摘要 → 用户确认 → 原账本安全 ZIP → 同一 SQLite 事务替换账本／设置／草稿；旧草稿请求隔离；安全副本可导出或再恢复 |
| 页面 | 首页、流水、账户、记账、短详情、余额更正的 SwiftUI 基础页面；无示例资产注入 |
| 工程 | Swift Package、XcodeGen、固定工具配置、手动 GitHub Actions、模拟器测试及未签名 IPA 脚本 |

数据库读写通过 Repository actor 协调；普通入账进一步把读取当前状态、领域判断、目标行写入与草稿处理放入同一 SQLite 写事务，避免旧快照覆盖较新流水。提交操作 ID 与编辑版本承担不同职责：前者防重复，后者防旧版本覆盖。余额更正重试沿用已存日期，即使重开数据库也不重复记账。外部文件在安全访问期间协调读取；普通入账与恢复均在提交前构造并核对快照，提交后直接返回，避免后续读取失败被误报为提交失败。
