| SQLite | schema 2；规范化核心列、账户呈现投影、精确整数金额、外键、操作唯一约束；普通新建／编辑只写目标行并同事务处理草稿；完整模型载荷与关键列互相核验；schema 1 可事务迁移，未知版本和坏库拒绝 |
| CSV ZIP | 新导出为 `ledger-core-v2` 固定 12 份 CSV，包含本版全部核心字段、账户呈现 ID、设置、草稿和退役操作 ID；字段字典、计数与原始字节 SHA-256 随包保存；精确 v1 契约仍可恢复 |
| 恢复 | 系统文件选择 → 校验与摘要 → 用户确认 → 原账本安全 ZIP → 同一 SQLite 事务替换账本／设置／草稿；旧草稿请求隔离；安全副本可导出或再恢复 |
| 页面 | 首页、流水、账户、记账、短详情、余额更正和账户模板选择的 SwiftUI 基础页面；无示例资产注入 |
| 工程 | Swift Package、XcodeGen、固定工具配置、手动 GitHub Actions、模拟器测试及未签名 IPA 脚本 |

数据库读写通过 Repository actor 协调；普通入账进一步把读取当前状态、领域判断、目标行写入与草稿处理放入同一 SQLite 写事务，避免旧快照覆盖较新流水。提交操作 ID 与编辑版本承担不同职责：前者防重复，后者防旧版本覆盖。余额更正重试沿用已存日期，即使重开数据库也不重复记账。外部文件在安全访问期间协调读取；普通入账与恢复均在提交前构造并核对快照，提交后直接返回，避免后续读取失败被误报为提交失败。

## 接下来的实现顺序

按用户最新安排优先形成完整业务链路，自动测试继续执行，中间包不逐轮交付。未完成的真机事项统一保留为后续验收项，不作为本地业务继续开发的前置等待。

1. 补齐 P1 尚缺的退款／回收关联、原额与净花费展示及关联删除影响处理；完善分类配置与后续预算、导入需要的标签／项目基础。新增实体和配置同时进入数据库迁移、CSV 完整恢复与旧版兼容测试。
2. 推进 P2 预算及导入：期间与范围、三种结转模式、历史修改重算；导入草稿、缺账户、分批提交、防重与规则。来源适配使用获准脱敏样本核对，尚未取得的格式不能称为支持；来源样本不齐时继续通用导入引擎与预算开发。
3. 推进 P3 贷款、报销借还及订阅：整期确认、手工维护未来计划、分次结算、确认月个人承担、非现金损失／减免和去重。
4. 推进 P4 投资：逐笔成交、持仓成本、手工收盘价和汇率、收益完整性及缺项提醒；API 不作为首版完成前提。
5. 完成 P5—P6 的物品、分析、预测、首页与自定义配置、可支持的 Widget、家庭飞牛 NAS／iCloud 备份及全量整合；再集中交付安装包，执行真机覆盖、恢复、主题／大字号、资源加载和长期使用验证。

工具链核验、原生视觉、输入与滚动体验、数据库查询及状态更新范围随以上模块持续治理。当前实际 Apple 工具链仍为 Xcode 26.6；Xcode 27／iOS 27 SDK、Q01—Q09 真机性能和扩展权限须取得各自证据，不用自动业务测试代替，也不将所有体验工作推迟到最后。

新发现只记录尚未决定的业务问题；已确认的手工贷款、日终补录、预算归属、家庭 NAS 与中性卡片规则不反复询问。

真机进度：2026-09-26 用户反馈 iOS 27 上签名安装与上述五项基础操作通过，设备精确系统 build 和已安装包哈希尚未记录；记录依据为用户反馈，而非自动化设备日志。运行 #19 已发布到固定目录，但账户模板、第三批计算器／复制／筛选及 profile 2 恢复尚未在该真机安装验证。构建继续使用 Xcode 26.6／iOS 26.5 模拟器基线；基础测试通过不代表 iOS 27 全部兼容性或全部产品功能已验收。
