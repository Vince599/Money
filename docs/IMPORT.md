# 通用 CSV 账单导入

更新：2026-09-28。当前为 P2 的普通流水导入基础批次，代码已实现，Core、Store 和 App Repository 已通过 Apple 运行 #39；该轮完整自动回归及 arm64 Release 构建成功。现有六条 UI 路径未覆盖导入页面专门操作，不是全部来源适配和 P2 完成结论。预算继续延期，未交付中间 IPA。

## 入口与流程

“账户 → 设置 → 导入账单 CSV”可导出通用模板、选择 UTF-8 CSV、继续历史导入批次。选择文件只创建持久草稿，不立即产生流水或正式账户；重开、退出、完整备份恢复均保留草稿及处理状态。完整 ZIP 备份仍走“完整备份与恢复”，不能作为普通导入。

1. 填写稳定的来源身份，例如“招商银行卡1234”；同一来源重导入时必须沿用，避免人为换身份绕开来源防重。来源交易号按字符串保存，保留前导零。
2. 保存文件为草稿，查看问题状态。按“来源身份＋原账户名＋币种”统一匹配已有账户，或在本批草稿中新建账户；转账同时映射转入账户。没有默认套用第一个账户或同名账户。
3. 单行核对账户、分类、主体、标签和项目；也可明确选择最多 200 行后，预览受影响行并批量改分类／主体或标签／项目。账户映射显示组内数量和示例，保存只影响本批未处理行，不建立长期规则。
4. 选择可导入行，预览新增流水数、新建账户数及受影响账户的导入前后余额；明确确认才提交。单次最多 200 行，其余保留；列表先显示 50 行，可继续加载。
5. 重复／失败／暂不处理的行可以明确选择并预览“跳过”；跳过不记账，但保留原始来源与处理状态。跳过并不永久占用来源交易号。已提交的普通流水可通过下述安全撤销流程处理；已跳过行不提供单独恢复为待处理的入口。

新账户可使用已有机构模板，确认类型／资产负债性质、币种、期初、日期及汇总开关；只在选中流水实际用到它时与流水同事务创建。未用到的账户仍留在本批草稿，不出现在正式账户页。取消账户映射页不保存本页修改，退出已保存的批次则保留草稿。

历史发生日期不因期初日期而被忽略。例如现有余额 10,000 元，导入上月支出 2,000 元，当前余额成为 8,000 元，消费归原发生日；之后可手动更正实际余额。导入不改变手动记账草稿和默认账户／主体配置。

## 连续核对与标签／项目（本轮）

- 单行可选择多个标签和一个项目。按文件顺序显示位置，底部“保存并上一笔／下一笔”先持久化当前草稿再切换；首末边界禁用对应方向。可跨越列表尚未加载的 50 行范围，已处理行只读切换。保存失败留在当前行，错误和未保存输入保留；“关闭”不保存本页未提交修改。
- 每次切换用最新批次版本初始化下一行，不沿用上一行编辑值；当前编辑页保留打开时的版本，批次被其他操作改动后拒绝旧页覆盖。正式流水仍须另行预览、确认，单行保存不入账。
- 批量标签明确选择保持、追加、移除指定项、替换全部或清空；追加去重并保留原标签顺序，移除可清理停用／缺失项。项目独立选择保持、设置或清除。默认都保持，不把空选择误当作清空。
- 点击预览后，逐行展示日期、金额及标签／项目的前后值，再明确确认；只改选中的未处理行。返回调整可重建预览。预览绑定业务快照，确认时目录、流水或批次发生变化均要求重新预览；同期手动记账草稿更新会保留。
- 草稿保留停用／缺失标签和归档／缺失项目，新增正式流水前必须修复，不用默认值掩盖。标签／项目参与重复核对摘要，修改后疑似重复需要重新核对；升级旧版草稿后的确认摘要也会重新计算。
- 标签批次没有增加长期自动规则、自动同商户选中或直接来源适配。普通流水批次撤销已在后续批次接入，见下文。连续核对为显式按钮，尚未增加滑动手势；大字号下按钮布局和导航状态仍需 Apple 页面验证。

此前 SQLite schema 6 沿用批次表；schema 5 打开时只在完整校验事务中推进版本，旧载荷缺失字段补为空，不重写旧字节。CSV profile 6 共 20 文件，新增 `import_row_tags.csv` 并在 `import_rows.csv` 末尾增加 `project_id`。旧 v1—v5 精确兼容；v5 保留原有导入状态并补空的标签／项目。完整备份同时包含未处理和已处理行的这些字段。

## 撤销本批普通导入（本轮）

批次页“查看撤销本批导入的影响”按整批已入账记录核对，包括此前多次部分提交的支出、收入和转账。页面先展示每笔记录、各账户当前余额及撤销后余额，再用明确确认执行；一笔后续编辑或关联冲突会阻止整个批次撤销，不悄悄只撤部分。

- 只有仍与导入原状完全一致的版本 1 事件可撤销。最终导入行的原始字段、稳定行／操作 ID、映射、标签、项目、创建时间已冻结，构成这类新增事件的回滚依据；逐字段重建后与当前事件精确比较，不靠同金额／同标题猜测。
- 后续编辑（包括改回原文字但版本已变）、记录已删除／缺失、退款／出售回收依赖都列出原因。可打开仍存在的流水自行处理；本入口不提供强制覆盖或连带删除收款。目录改名、停用、项目归档本身不改事件，不会被误判为流水已编辑。
- 仅撤回本批现金事件和原期间消费影响；账户、账户期初、余额更正、其他流水与设置保留。本批曾创建的账户也保留，不自动清空或删除账户。来源合并不修改原流水，因此撤销仅解除来源；会修改原流水字段的合并及其前版本恢复尚未实现。
- 预览绑定完整业务快照，期间任何业务变化都要求重新核对。写入时重新读取当前账本，删除事件、登记已消费操作 ID、标记行已撤销和关闭批次同事务提交；失败全部回滚。成功响应丢失后在精确已提交状态重试，不再次改变余额；手动记账草稿保留事务时的最新值。
- 撤销后原批次只读，保留原始行、最终映射、原跳过及未处理内容，并记录撤销时间。旧提交按钮／旧预览不能重放。需要重导入时重新选择 CSV 创建新批次，重新映射、核对，用新内部 ID 入账；明确整批撤销会释放对应源交易身份，普通手动删除流水仍保留原来源防重记录。
- 未入账的纯草稿无需资金撤销；暂不提供删除批次、重新打开已撤销批次或恢复已跳过行。未处理内容不是正式交易，不会因关闭批次而产生现金变化。

此前 schema 7 在既有批次载荷增加可空 `revertedAt`；schema 5／6 在完整读取校验事务中推进版本，缺失字段补 nil，不改写旧载荷。CSV profile 7 仍为 20 文件，批次增加成对可空的 `reverted_at_utc`／`reverted_at_bits`，行状态增加 `reverted`。保留精确 v1—v6 读取，v5／v6 的旧已提交批次在状态可核对时也可安全撤销。撤销状态、源证据和已消费操作 ID 随完整备份恢复，不重新扣款；只有一列撤销日期、无已消费 ID 的撤销状态、撤销后仍存在原事件等不一致数据会被拒绝。schema／profile 8 增加长期规则，版本 9 扩展规则动作，当前版本 10 增加来源合并关联。

## 长期规则与逐字段确认

入口为设置 → 导入规则，可新建、编辑、调整优先级和停用。单行核对页另有“将这次选择保存为规则”：预填当前来源身份和可编辑的标题条件（标题空时使用来源分类条件），账户／转入账户／分类／主体／追加标签／项目动作开关默认均关闭，用户独立选择。只保存规则，不隐式保存本行；不会默认记住整笔金额、日期或备注。尚未正式建立的草稿账户不能作为启用规则的目标。

- 规则保存稳定 ID、名称、来源身份范围、优先级、启用状态、版本、可选币种及金额范围、条件与动作。来源身份精确匹配，留空适用全部来源。优先级数字越小越优先，范围 0—10000。
- 标题、备注、来源分类和来源账户支持区分大小写的“等于／包含”；方向支持支出、收入、转账的精确比较。所有条件同时满足（AND），最多 12 条。金额使用精确最小货币单位，边界包含等于，填写任一边界必须指定币种；至少有一个文字条件或金额边界。这里只读取公开模板已有的原始列，不虚构商户、商品、代付成员等未导入字段。
- 动作支持付款／收款账户、转入账户、分类、主体、追加标签、设置项目，各字段独立。每条规则最多一个追加标签动作；采用后保留原有标签及顺序，不重复追加已有标签。多个规则推荐不同标签时仍列为冲突，本次明确选择一个，不自动合并所有标签。需要一次追加多个、替换／移除／清空标签或清除项目时，继续使用既有“本批标签／项目”入口。
- 转入账户只为转账提供建议，需与该行币种一致；转出与转入字段组合选择后不能指向同一账户。此类选择错误在预览阶段指出来源交易号，整次预览失败，不部分保存。项目规则只设置未归档项目，不隐式清除原项目。
- “保存本行并查看规则建议”先保存当前手工映射，再读取最新规则与该行。匹配规则按字段汇总，展示每个建议的规则名称、优先级、版本；不同值全部列为冲突。最高优先级唯一值可标为建议，同级不同值不选赢家，不按数据库顺序暗选。
- 每个字段默认“保持当前值”，包含已有手工值和默认主体。用户明确选字段 → 预览前后值 → 确认保存，仅修改本行草稿；不直接入账、不改变其他行、未选字段或手工记账草稿。不在读取文件、打开页面或修改规则后自动应用。
- 规则预览绑定完整业务快照及规则版本；期间规则、目录、批次或账本变化，旧预览拒绝覆盖，需重新读取。规则编辑本身也要求原版本一致。更新规则不重写已入账流水；已入账、已跳过、已撤销及关闭批次不接收规则建议。
- 目标账户、二级分类／其父级、主体、标签停用／缺失，或项目归档／缺失时，整条规则暂停建议，并保留配置供修复。管理列表明确显示“已暂停”；编辑资料时列出关联规则。恢复可用后，配置为启用的规则恢复建议。单行的币种／分类方向不兼容会提示并排除相应动作；其他可用字段仍可核对。失效规则可停用保存，修复后再启用。

此前 schema 8 新建 `import_rules` 表，投影与完整载荷互校；schema 1—7 的迁移在打开校验事务中完成，旧批次、流水和草稿载荷不重写，失败回滚版本和新表。CSV profile 8 共 23 文件，新增规则、条件、动作三表，所有字段为独立列。精确 v1—v7 恢复时规则为空；v8 完整保存规则状态和可修复的失效目标，不静默丢弃。schema 9 扩展现有规则载荷中的动作枚举；schema 8 在打开校验事务中推进版本，不重写旧载荷，失败回滚。CSV profile 9 仍为 23 文件，扩展动作字段枚举和引用字典；精确 profile 8 保留原规则动作，旧字典不接受新枚举。规则存储与应用沿用整本事务，尚无大数据性能达标结论。

## 所选行的批量规则核对

在批次页选择待处理行，打开“核对所选行的规则建议”，一次最多 200 行；可选择当前已显示的待处理行，包含尚缺账户或分类的行。所有建议来自同一次账本和规则快照，按来源文件顺序展示，每行可展开查看当前值、候选、冲突、规则名称／优先级／版本和不可用提示。

- 默认全部保持当前值。点击“仅填充无冲突的空字段”才会选择空账户／空转入账户／空分类／空项目的唯一建议，不改已有映射和默认主体；较低优先级的不同建议同样算冲突，不进入快捷填充。已逐行选择的值保留。追加标签不参加快捷填空，需要逐行选择。
- 有冲突或希望更改已有值时，逐行、逐字段明确选择；选择只留在当前核对页面，尚未修改草稿。清除选择可全部恢复为保持当前值。
- 预览只列实际变化，显示行数、字段数和每行前后值；相同值不算修改，完全无变化不能提交。确认时一次保存所选变化，批次版本只增加一次，不创建流水。未选行、原文、未选字段、规则配置及手工记账草稿均保留。
- 预览和保存都核对业务快照，规则、目录或任意批次变化后拒绝旧内容覆盖；重新读取明确清除本次选择，需再核对。已处理行、已关闭批次、未知行和超过 200 行整体拒绝，不悄悄过滤后提交部分。
- 数据库读取当前状态、校验、写入和结果核验在同一事务内。失败全部回滚，可在状态未变化时重试；已成功提交的旧预览拒绝再次保存。备份保存确认后的映射；未确认的页面选择为临时状态，关闭页面后需重选。

批量核对不新增单独的持久状态，当前使用 schema 10／CSV profile 10（23 文件）。批量核对只做一次完整业务校验，逐行应用复用单行字段校验，避免每行复制整批数据；这不代表已通过 1 万行性能验收。

## 导入历史检索

导入账单页可组合选择来源身份、全部／未撤销／已撤销批次、行处理状态，并搜索来源交易号、标题或备注。关键词去除首尾空白、忽略大小写、按字面匹配，`%`、`_`、引号和正则字符没有特殊含义；无标题行沿用来源分类作为展示标题，也可搜索。来源身份精确匹配，关键词不搜索文件名、来源账户名或金额。状态和关键词须匹配同一行，不因为同批另一行符合就扩大结果。

- 批次显示匹配行数／总行数，沿用批次倒序；每次展示 50 个批次。点入携带行状态和关键词，批次内按原文件顺序显示，每次增加 50 行。空结果与尚无导入记录分别提示，可清除条件。
- 状态覆盖待处理原行、已导入、已合并来源、已解除来源、已跳过、已撤销。已撤销批次里的未处理原行仅供核对，不因筛选而重新开放提交。
- 筛选变化清空勾选并回到首批 50 行；全选只取当前已显示的可导入／待处理行，最多 200 行。旧查询期间禁用依赖核对结果的操作，成功后移除已处理或隐藏行的勾选，读取失败可重试。筛选只负责查找，资金提交继续走原有预览和版本校验。
- 打开单行时固定本次筛选得到的行 ID 范围，“上一笔／下一笔”仅在该范围按文件顺序移动，可以跨越尚未展示的 50 行分页。编辑或合并导致该行不再匹配时，当前核对页仍保留它；关闭后列表按最新状态重查。
- 查询有 200 ms 输入防抖，文字扫描放到后台，结果绑定筛选和账本修订，过期返回不覆盖新条件；批次内核对另绑定已显示行数。查询条件暂存页面，不是持久配置；不增加业务字段或迁移，沿用 schema 10／profile 10（23 文件）。现有账本仍整本驻留内存，未宣称大数据性能达标。

## 合并来源，保留已有流水

单行核对页 → “保存本行并核对合并来源”：先保存映射，再展示已入账候选。当前仅接受普通支出、收入或转账，要求账本上海日期同日、方向／币种／金额／账户相同，转账还要求相同转入账户。候选来自现有正式流水，不把待处理行彼此合并，也不以同金额推定为同一笔。来源状态须为 success、日期有效且非未来、映射可用；来源交易号重复或已处理时先解决冲突。

- 选候选后并列查看标题、精确日期、分类、主体、备注、标签、项目。每个不同字段都需要独立勾选“保留已有流水”，不能一键默选冲突。资金字段不符不进入此入口。需要采用来源值时先退出，单独编辑目标后重新核对。
- 确认只附加来源，不改变已有流水任何字段、版本或资金，不创建第二笔流水／账户。原始 CSV 列、来源身份和交易号继续保存在导入行；行状态为 `merged`，指向已有流水。其独立操作 ID 登记为已消费，普通导入、再次合并和同来源重导入不能重放。
- 流水详情和删除影响页可展开来源原文，打开批次或单独解除某份来源。删除目标（含整组删除中的子记录）或撤销原始导入前，必须先解除其他批次的活跃来源关联；旧删除预览也不能绕过新关联。
- 单独解除有独立影响预览，保留已有流水与全部后续编辑／回收，只将本行标为 `unlinked`；历史目标 ID、原文与已消费操作 ID 保留，其他行和来源不变，批次不关闭。这样即使同批其他流水已被编辑、整批撤销受阻，仍能明确处理这一份关联。
- 整批撤销对来源合并只解除本批关联，对新增流水继续执行原状与后续依赖检查。纯来源批次不改变现金；混合批次同时预览新增流水的余额影响和将解除的来源。保留已有流水及后续编辑，不回滚整个账本。若修改了新增流水，仍阻止整批盲目撤销。
- 合并、单独解除和整批撤销均绑定当前业务快照，事务失败整体回滚，精确成功状态重试不重复执行。手工记账草稿保留事务时最新值。已解除／已撤销的原行不能重新提交；如需重导入须新建 CSV 批次重新核对，明确解除后释放该来源身份。

schema 10 在既有批次载荷增加可空 `mergedEntryID`，无新 SQL 表／列，schema 9 迁移不重写旧载荷。profile 10 仍为 23 个 CSV，`import_rows.csv` 追加 `merged_entry_id` 列，状态增加 `merged|unlinked`；活跃 merged 必须指向现存流水，unlinked／reverted 保存历史引用。精确 profile 1—9 保持各自契约，旧行关联补 nil；缺目标、未消费操作、伪造状态或混搭旧字典拒绝恢复。完整备份覆盖活跃及已解除关联。

当前是“不改流水字段的来源合并”首批；还未实现两笔已入账流水合并、资金差异选值合并、订单证据的一对多金额分配、拆分支付、商户订单自动匹配及高确定性批量合并。不得将此入口用于把 100 元订单合并到 30 元／70 元支付而造成资金错误。

## 公开模板 v1

模板：[ledger-import-v1.csv](../templates/ledger-import-v1.csv)。仅含一笔合成示例，导入前替换为真实整理数据；App 导出使用同一字段契约。当前识别精确表头和列序，不推测来源格式。

| 字段 | 规则 |
|---|---|
| `source_id` | 来源身份内稳定、唯一的实际支付／收款 ID。必填；不得每次转换时重新编号。缺少稳定 ID 时暂留核对，不能假装已可靠去重。 |
| `occurred_at` | 含时区的 ISO 8601，例如 `2026-08-15T12:30:00+08:00`，可含 1—6 位小数秒。无时区、非法日期、闰秒拒绝入账；不猜手机时区。 |
| `type` | 当前仅 `expense`、`income`、`transfer` 可进入普通确认流程。 |
| `amount` | 正金额，最多两位小数；不接受算式，入账使用精确最小货币单位。零额、负数和异常格式暂留。 |
| `currency` | 当前支持 `CNY`／`HKD`／`USD`，必须与账户币种一致。 |
| `account` | 来源付款／收款账户原文，仅作待匹配依据；不是账户外键。 |
| `destination_account` | 转账的来源转入账户名，其他类型可空。 |
| `category` | 来源分类原文供核对；当前不按名称自动分配分类。 |
| `title`、`note` | 原文保存，映射后入账；可空。 |
| `status` | 只有精确的 `success` 可提交。失败／关闭／未知状态保留并提示核对。 |

接受 UTF-8（可有 BOM）、LF／CRLF、有或无末尾换行，支持带引号的逗号、多行字段和双引号转义；反斜杠按普通字符处理，不使用完整备份的 `\N` 转义规则。空单元格表示空字符串。文件最大 16 MiB、最多 10,000 行数据、单字段小于 64 KiB；结构损坏时整份文件拒绝，不创建半份草稿。

未来日期暂留导入草稿，不直接进入已发生账本；未来计划实体尚未接入。退款、出售回收、报销、借还款、贷款期次、证券等特殊类型当前不从普通导入自动入账，以免绕过业务关联和确认。

## 防重与提交边界

- 同来源身份＋同源交易号已导入或已合并，且未撤销／解除，原始字段一致：显示“已导入”，用户可明确跳过。即使正式流水后来被编辑或删除，已消费来源身份仍保留，不重放扣款。
- 同源 ID 内容不同：留待冲突处理，不当成新收支，也不静默覆盖。一个批次内相同 ID 的待处理行都需核对，可先明确跳过重复行。
- 同日（账本上海日期）、同账户、同方向、同币种金额相同：只作疑似提示，包含正式流水和本批已映射的其他候选；可查看全部候选。确认“保留为独立交易”后保存核对结果，不自动删除或合并。
- 独立交易确认绑定当前候选内容和对方版本的摘要；分类／账户等关键映射或对方内容变化会重新提示。跨来源订单证据、智能匹配排序与一对多支付分配仍待后续实现。
- 预览绑定完整业务快照；提交事务重新读取并核对，账本或批次变化则要求重新预览。手动草稿更新不使资金预览失效，但提交保留事务时的最新手动草稿。
- 同一确认的成功响应丢失后，精确已提交状态下重试返回同一结果；其他旧预览拒绝。账户、流水、处理状态与操作 ID 一起提交，任一失败全部回滚。
