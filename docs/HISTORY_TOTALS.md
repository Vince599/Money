# 流水日汇总

2026-09-28 接入流水日期标题下的每日收支，沿用灰白页面和现有金额格式。此批不涉及预算、图表、每日分类分析或汇率换算。

## 汇总口径

- 按账本上海日历分日，按当前搜索／筛选条件汇总，包括该日符合条件但尚未加载到列表的流水。不是当前页小计，也不把筛选之外的记录加入汇总。
- CNY／HKD／USD 分列，不相加或折算。`expense` 计支出，`income` 计收入，`refund`／`recovery` 单列退款／回收；原购买仍显示原额，不用回收抵减当日支出。
- 转账只显示笔数，不计日收入或支出；余额更正是独立调整，不混入流水日收支。未纳入总资产的账户仍正常参与消费查询，只有明确的账户筛选会排除记录。
- 存储金额以整数最小单位流式累加，用 Int128 计算。某一币种某一列超出 Int64 显示范围时，该列显示“超出显示范围”，其他列和流水继续可见；不截断、不绕回、不将未知值显示为零。
- 筛选有结果时也显示“已应用搜索或筛选”和清除入口；空结果保留原有清除入口。汇总随同列表刷新，读取失败显示错误，不伪造空汇总。

## 分页与一致性

Core 提供共享 `EntryDailyAccumulator` 及 `EntryDaySummary`，App 的日期分组复用相同日历。SQLite 在行列表、总数所在的同一个读事务，使用同一条件查询当前页涉及日期的 `kind`／`currency`／`amount_minor`／`occurred_at` 投影。汇总查询不带 LIMIT 或续页边界，日期／金额／来源／关联等用户条件保留。

若一个日期跨页，第一页取得整日汇总，分页令牌携带最后一天的完整值；后续页复用该值，只查询新出现的日期。页面合并同一天时替换汇总而不相加，避免翻页重复计数。令牌仍绑定 Store、筛选、数据库改动计数与 data_version；编辑、删除或来源变更后旧缓存拒绝使用并重读。

数据已在打开和写入时按既有完整校验规则检查，实际返回的流水仍核对 payload／投影。汇总只读取投影并检查类型、金额和日期，不额外解码尚未展示的整日流水载荷；这不是每页重新校验整本账本。没有新增表、持久缓存或 CSV 配置，继续 schema 10／profile 10。

首次出现的日期需要扫描其符合条件的全部投影，特别是同一天大量流水时；复用跨页汇总减少重复读取，但没有十万笔／真机时延达标结论。来源筛选自身每页读取批次的既有限制仍在，见[性能基线](PERFORMANCE_BASELINE.md)。
