# 日常流水分类与图标设计建议

2026-09-26 用户已要求将本方案写入文档供后续开发参考，内容已纳入 [正式分类附录](../IOS_CATEGORIES.md) v1.5 及 [主设计文档第 8 节](../IOS_DESIGN.md#8-分类主体标签与项目)。本文件保留简明讨论摘要；开发和后续更新以正式分类附录为准。逐类范围、包含／排除和争议案例见 [分类使用指南](CATEGORY_GUIDE.md)，后续仅在设置 → 使用指南展示。本轮仅更新文档，未修改 App 或分类种子。

方案保留现有顺序、稳定 ID 和两级结构；一级默认显示名称“日常购物”简化为“购物”，“订阅与数字服务”简化为“数字服务”。已有账本不因此被自动改名或覆盖用户配置。

基础目录共 **100 个节点**：支出 15 个一级、70 个二级；收入 5 个一级、10 个二级。交通下的“骑行租车”仅为待新增建议，不计入基础目录。默认快速入口展示常用分类，完整目录保留在分类管理与搜索中。

| 一级分类 | 一级图标 | 二级分类及各自图标 |

| 经营收入 | 商店 | 经营所得（商店）；租金（房屋与钥匙） |

## 三、容易混淆的边界

| 场景 | 推荐归属或处理 |
|---|---|
| 旅行中的机票、酒店、餐饮 | 分别归交通／机票、居住／住宿、餐饮下对应分类，以同一旅行项目汇总。 |
| 外卖咖啡、外卖餐食 | 咖啡归饮品，餐食归外卖；配送渠道不覆盖更明确的商品用途。 |
| 杯子、咖啡机、咖啡豆 | 杯子归厨具餐具，咖啡机归家用电器，作为冲泡原料的咖啡豆归食材。 |
| 清洁用品与保洁服务 | 用品归购物／日用品；服务归生活服务／家政洗护。 |
| 护肤品与理发 | 商品归购物／美妆护理；服务归生活服务／美容理发。 |
| 家电、数码整机与维修 | 家电整机归家用电器，电脑等按数码用途归类；非房屋、非车辆维修归生活服务／维修服务。 |
| 电脑配件与数码配件 | CPU、显卡、内存、键鼠、显示器归电脑配件；手机壳、通用线材、充电器归数码配件。 |
| 存储硬件、云盘与宽带 | NAS、独立存储设备归网络与存储；云盘订阅归云服务与存储；宽带服务归通信／宽带。电脑内部升级部件优先电脑配件。 |
| 课程、书籍与数字会员 | 知识技能课程归课程培训，纸质或电子书（含小说）归图书资料；运动训练课程归运动健身；通用软件、AI、影音或资讯服务归对应数字服务。 |
| 运动服饰与健身 | 运动衣、鞋、包归购物／服饰鞋包；健身会籍、私教及非服饰非数码运动器材归运动健身；智能手表等仍归数码。 |
| 游戏、健身与周期付款 | 游戏软件及游戏内消费归游戏；健身年卡归运动健身；付款周期由订阅功能记录，按余额扣费的充值先记储值转账。 |
| 看病、检查与保险保费 | 诊疗住院归门诊住院；独立体检及专项检查归检查体检，成套诊疗费用不强制拆单；保费归保险。 |
| 礼物与亲属代付 | 明确赠送的物品归礼物，无需归还的现金赠与归礼金红包；普通亲属代付按实际用途与主体归类。 |
| 房租押金、充值、借还本金 | 按相应账户或往来款事件管理，不能因现金流出而当作普通消费。 |
| 信用卡还款 | 按账户及负债结算处理，避免与原消费重复计支出；实际利息、手续费单独归财务费用。 |
| 报销垫付与回款 | 沿用独立报销流程；回款不计普通收入。转为个人承担时，按确认月份和实际用途计消费。 |
| 已关联购买的退款或二手回收 | 保留原支出金额，关联支出回收事件；不计普通收入，不释放原预算。详情展示回收额与净花费。 |
| 记账前购入物品的二手出售 | 可由用户手动选择普通收入及分类，不强制补录原购买，不自动创建回收事件。 |
| 税费、投资费用及未知交易 | 证券交易税费沿用投资费用组件；个人税费可启用扩展模板；用途未知保持待分类，不能自动填入其他明确支出。 |

## 四、按需扩展

现有目录不必继续默认铺开。以下为模板或边界建议，不改动上述 100 个节点。

- **交通／骑行租车（待新增）**：共享单车、共享电单车、自驾租车的实际使用费；图标建议自行车。押金仍按往来款处理，实际燃油或充电费归燃油充电。不为每种租赁交通工具分别建类。
- **宠物模板**：食品、医疗、用品、服务；一级爪印。用户启用后，宠物用途优先进入该模板，避免同笔支出在宠物与一般食品、医疗之间摇摆。
- **育儿与照护模板**：保留既有喂养、用品、托育及护理、照护服务建议；一级分别为婴儿、双手。启用时明确专用用途的归属，家庭成员仍由主体或标签表达。
- **税费与行政模板**：个人税费、证件办理；一级文件印章。无需为每种证件或税费增加默认二级。
- **车辆购置、保险理赔**：当前基础目录未单列，不能为凑齐目录塞进车辆养护或保费。车辆购置需先与物品、资产及贷款事件口径协调；理赔需区分已有垫付回收与独立赔付款的性质。这两项先保留为业务边界，后续需要时再确定事件与分类。

## 五、统一图标及选择方式

1. **统一风格**：全部使用同一套 SF Symbols，以单色、统一字重与视觉尺寸展示。不混用 emoji、彩色素材或来自不同图标体系的图形。语义相近的分类可以共用图形，由名称辅助识别。
2. **默认图标**：每个一级、二级预置一个有效符号；用户无需先配置即可记账。平台不支持的符号以已验证的通用标签图标 `tag` 显示回退，保留原图标标识，不静默改写用户选择，也不出现空白或问号。
3. **默认颜色**：沿用现有一级基色，二级默认继承。分类色仅用于图标及其浅色小底；标题、整行背景保持统一中性色。金额使用独立的收支颜色。
4. **图标库选择**：编辑分类时，点击当前图标进入统一图标库，可搜索或按主题浏览，选中后在分类名称旁即时预览；保存后应用到该分类的记账入口、列表和统计。
5. **恢复默认**：图标与颜色分别提供恢复默认。二级恢复默认颜色时重新跟随父级；只改一级图标不覆盖二级独立图标。
6. **更改不改归属**：图标、颜色、显示名称的编辑不更换稳定 ID，也不改变历史流水和预算范围。移动、合并二级分类仍执行原有影响预览规则。

## 六、本次建议摘要

- 保留 15 个支出一级、5 个收入一级及全部 80 个二级，顺序不变。
- 简化两个一级显示名称为“购物”“数字服务”，后者采用用途导向的应用窗口图标。
- 一级和二级均有默认图标；用户可从统一图标库更换并恢复默认。
- 用明确边界和常用入口减少选择负担，不通过删减用户已需要的数码细分、合并通信或改动退款口径来压缩目录。
